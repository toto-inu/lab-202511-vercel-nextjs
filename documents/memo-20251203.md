## 発見・修正したバグ

### バグ1: plan.priceがnullの場合のエラー

**エラー内容:**
```
TypeError: Cannot read properties of null (reading 'toLocaleString')
at PlanChangeDialog.tsx (128:40)
```

**原因:**
- データベースのPlanテーブルで`price`がnull許容だが、型定義が`number`のみだった
- `plan.price.toLocaleString()`を直接呼び出していた

**修正:**
- Plan型定義に `| null` を追加
- null合体演算子を使用: `(plan.price ?? 0).toLocaleString()`

### バグ2: formatLimit関数でのundefinedエラー

**エラー内容:**
```
TypeError: Cannot read properties of undefined (reading 'toString')
at formatLimit (PlanChangeDialog.tsx:87:18)
```

**原因:**
- `maxProjects`, `maxUsers`, `maxTodos` がnullまたはundefinedの可能性があった
- 型定義が`number`のみでnullチェックがなかった

**修正:**
- `formatLimit` 関数の引数型を `number | null | undefined` に変更
- null/undefinedチェックを追加: `if (limit === null || limit === undefined || limit === -1) return '無制限'`

## 技術的な学び

### 1. グローバル管理者の権限チェック

`requireGlobalAdmin()` を使用して、管理者専用のServer Actionsを保護しました。

```typescript
export async function getAllTenantsWithStats() {
  await requireGlobalAdmin()
  // ...
}
```

### 2. リソース使用状況の取得

既存の`getResourceUsage()`関数を利用して、各テナントのプロジェクト・ユーザーの使用状況を取得しました。

```typescript
const tenantsWithStats = await Promise.all(
  tenants.map(async (tenant) => {
    const usage = await getResourceUsage(tenant.id)
    return {
      ...tenant,
      usage: {
        projects: usage.projects,
        users: usage.users
      }
    }
  })
)
```

### 3. 使用率の色分け

使用率に応じて視覚的なフィードバックを提供：

```typescript
const getUsageColor = (percentage: number, isUnlimited: boolean) => {
  if (isUnlimited) return 'bg-gray-300'
  if (percentage >= 100) return 'bg-red-500'
  if (percentage >= 80) return 'bg-yellow-500'
  return 'bg-blue-500'
}
```

### 4. nullセーフな型定義

データベースのnull許容カラムに対応した型定義の重要性を学びました。

```typescript
interface Plan {
  id: string
  name: string
  price: number | null          // null許容
  maxProjects: number | null    // null許容
  maxUsers: number | null       // null許容
  maxTodos: number | null       // null許容
}
```

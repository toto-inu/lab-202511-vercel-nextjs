# 権限設計（サマリ版）

## 🔐 権限チェックの順序

```
1. 認証チェック（ログイン済み？）
   ↓
2. Plan制限チェック（機能・リソース上限）
   ↓
3. Tenant Roleチェック（組織内権限）
   ↓
4. Project Roleチェック（プロジェクト内権限）
```

## 👥 Tenant Role

| Role | 権限 |
|------|------|
| **OWNER** | 全権限、プラン変更、Tenant削除 |
| **ADMIN** | ユーザー管理、プロジェクト作成・管理、全プロジェクトアクセス |
| **MEMBER** | 割り当てられたプロジェクトのみアクセス |

## 📂 Project Role

| Role | 権限 |
|------|------|
| **ADMIN** | プロジェクト設定、メンバー管理、Todo全権限 |
| **EDITOR** | Todo作成・編集・削除（自分のTodo） |
| **VIEWER** | 閲覧のみ |

## 📊 Plan制限

| 制限 | FREE | PRO | ENTERPRISE |
|------|------|-----|------------|
| プロジェクト | 3 | 50 | 無制限 |
| ユーザー | 5 | 50 | 無制限 |
| Todo/プロジェクト | 100 | 1,000 | 無制限 |
| API | ❌ | ✅ | ✅ |
| カスタムロール | ❌ | ❌ | ✅ |
| 監査ログ | ❌ | ❌ | ✅ |

## 🔧 実装パターン

```typescript
// Server Action
export async function createTodo(projectId: string, data: TodoData) {
  // 1. 認証
  const user = await getCurrentUser();

  // 2. Plan制限
  const limitCheck = await checkResourceLimit(tenantId, 'todos', projectId);
  if (!limitCheck.allowed) throw new Error('上限到達');

  // 3. Tenant Role（自動）
  // 4. Project Roleチェック
  await requireProjectRole(projectId, ['ADMIN', 'EDITOR']);

  // 作成処理
}
```

## 🌟 特殊ケース
- **Tenant OWNER/ADMIN**: 全プロジェクトで自動的にProject ADMIN権限
- **グローバル管理者**: すべての権限をバイパス

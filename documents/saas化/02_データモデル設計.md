# データモデル設計

## 概要

SaaS化に向けたマルチテナント対応のデータベーススキーマ設計。

## ER図（概念）

```
Plan
  ↓ (1:N)
Tenant ←→ (N:M) ← User
  ↓ (1:N)           ↓
Project          TenantMember (role)
  ↓ (1:N)           ↓
Todo ←─────────── ProjectMember (role)
  ↓
Assignee
```

## モデル詳細

### Plan（プラン）

SaaS製品としてのプラン定義。

```prisma
model Plan {
  id          String   @id @default(cuid())
  name        String   @unique  // "FREE", "PRO", "ENTERPRISE"
  displayName String             // "Free Plan", "Pro Plan", "Enterprise Plan"
  description String?

  // 機能制限
  maxProjects       Int?     // nullは無制限
  maxUsersPerTenant Int?
  maxTodosPerProject Int?

  // 機能フラグ
  features          Json     // { "advancedReporting": true, "apiAccess": false, ... }

  // 価格情報（将来の拡張用）
  price             Decimal? @db.Decimal(10, 2)
  billingCycle      String?  // "MONTHLY", "YEARLY"

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  tenants   Tenant[]
}
```

**機能フラグ例**:
```json
{
  "advancedReporting": false,
  "apiAccess": false,
  "customRoles": false,
  "auditLog": false,
  "prioritySupport": false
}
```

### Tenant（テナント）

組織・企業単位。

```prisma
model Tenant {
  id          String   @id @default(cuid())
  name        String
  slug        String   @unique  // URL用: acme-corp
  description String?

  // プラン関連
  planId      String
  plan        Plan     @relation(fields: [planId], references: [id])

  // サブスクリプション状態
  status      TenantStatus @default(ACTIVE)  // ACTIVE, SUSPENDED, CANCELLED
  trialEndsAt DateTime?

  // 設定
  settings    Json     @default("{}")  // テナント固有設定

  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  // Relations
  members     TenantMember[]
  projects    Project[]
}

enum TenantStatus {
  ACTIVE
  TRIAL
  SUSPENDED
  CANCELLED
}
```

### User（ユーザー）

Clerkユーザーと紐づく。複数Tenantに所属可能。

**注意**: 既存の`role` Enumフィールドは削除し、TenantMember/ProjectMemberでロールを管理します。

```prisma
model User {
  id        String   @id @default(cuid())
  clerkId   String   @unique
  email     String   @unique
  name      String?
  avatarUrl String?

  // グローバル管理者フラグ（システム管理者用）
  isGlobalAdmin Boolean @default(false)

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  // Relations
  tenantMemberships  TenantMember[]
  projectMemberships ProjectMember[]
  createdTodos       Todo[]         @relation("TodoCreator")
}
```

**移行メモ**: 既存のUserモデルから`role` Enumフィールドを削除します。既存のADMINユーザーはdefault TenantのOWNERに、一般ユーザーはMEMBERに移行します（詳細は[07_移行計画.md](./07_移行計画.md)参照）。

### TenantMember（テナントメンバーシップ）

ユーザーとTenantの中間テーブル。Tenantレベルのロールを保持。

```prisma
model TenantMember {
  id       String @id @default(cuid())

  userId   String
  user     User   @relation(fields: [userId], references: [id], onDelete: Cascade)

  tenantId String
  tenant   Tenant @relation(fields: [tenantId], references: [id], onDelete: Cascade)

  role     TenantRole @default(MEMBER)

  // 招待・参加関連
  invitedBy   String?
  invitedAt   DateTime?
  joinedAt    DateTime  @default(now())

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@unique([userId, tenantId])
  @@index([tenantId])
  @@index([userId])
}

enum TenantRole {
  OWNER      // テナント所有者。全権限
  ADMIN      // テナント管理者。ユーザー管理、プロジェクト管理
  MEMBER     // 一般メンバー。割り当てられたプロジェクトのみアクセス
}
```

### Project（プロジェクト）

Tenant内の作業単位。Todoをグループ化。

```prisma
model Project {
  id          String  @id @default(cuid())
  name        String
  description String?
  slug        String  // テナント内で一意

  tenantId    String
  tenant      Tenant  @relation(fields: [tenantId], references: [id], onDelete: Cascade)

  // プロジェクト設定
  settings    Json    @default("{}")
  archived    Boolean @default(false)

  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  // Relations
  members     ProjectMember[]
  todos       Todo[]

  @@unique([tenantId, slug])
  @@index([tenantId])
}
```

### ProjectMember（プロジェクトメンバーシップ）

プロジェクトレベルのロール。

```prisma
model ProjectMember {
  id        String @id @default(cuid())

  userId    String
  user      User    @relation(fields: [userId], references: [id], onDelete: Cascade)

  projectId String
  project   Project @relation(fields: [projectId], references: [id], onDelete: Cascade)

  role      ProjectRole @default(VIEWER)

  joinedAt  DateTime @default(now())
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@unique([userId, projectId])
  @@index([projectId])
  @@index([userId])
}

enum ProjectRole {
  ADMIN      // プロジェクト管理者。メンバー管理、設定変更
  EDITOR     // 編集者。Todo作成・編集・削除
  VIEWER     // 閲覧者。Todoの閲覧のみ
}
```

### Todo（改修）

既存Todoモデルにテナント・プロジェクト対応を追加。

```prisma
model Todo {
  id          String   @id @default(cuid())
  title       String
  description String?
  completed   Boolean  @default(false)

  // マルチテナント対応
  tenantId    String
  projectId   String
  project     Project  @relation(fields: [projectId], references: [id], onDelete: Cascade)

  // 作成者
  createdById String
  createdBy   User     @relation("TodoCreator", fields: [createdById], references: [id])

  // 担当者（既存のAssignee）
  assigneeId  String?
  assignee    Assignee? @relation(fields: [assigneeId], references: [id], onDelete: SetNull)

  // 優先度・期限（将来拡張）
  priority    TodoPriority @default(MEDIUM)
  dueDate     DateTime?

  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  @@index([tenantId])
  @@index([projectId])
  @@index([createdById])
}

enum TodoPriority {
  LOW
  MEDIUM
  HIGH
  URGENT
}
```

### Assignee（変更なし）

担当者情報。既存モデルをそのまま維持。

```prisma
model Assignee {
  id        String   @id @default(cuid())
  name      String
  email     String   @unique
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  todos     Todo[]
}
```

## インデックス戦略

### パフォーマンス重視のインデックス

```prisma
// TenantMember
@@index([tenantId, role])  // テナント内のロール別メンバー検索

// ProjectMember
@@index([projectId, role]) // プロジェクト内のロール別メンバー検索

// Todo
@@index([tenantId, projectId, completed])  // テナント・プロジェクト・完了状態での検索
@@index([createdById, completed])           // ユーザーのTodo一覧
@@index([assigneeId, completed])            // 担当者のTodo一覧
```

## データ整合性制約

### 必須制約

1. **Tenant分離の保証**
   - すべてのクエリで`tenantId`フィルタ必須
   - Prisma Middlewareで強制

2. **ロール階層の保証**
   - TenantMember.OWNER → 全Project権限
   - ProjectMember権限は所属Tenantメンバーのみ

3. **カスケード削除**
   - Tenant削除 → Project/TenantMember削除
   - Project削除 → Todo/ProjectMember削除
   - User削除 → TenantMember/ProjectMember削除

## マイグレーション戦略

### Phase 1: 基本スキーマ追加

1. Plan, Tenant, TenantMemberモデル追加
2. Project, ProjectMemberモデル追加
3. 既存Todoモデル拡張（tenantId, projectId追加）

### Phase 2: データ移行

1. デフォルトTenantの作成（既存データ用）
2. デフォルトProjectの作成
3. 既存TodoにtenantId/projectIdを設定
4. ユーザーをデフォルトTenantに追加

### Phase 3: 制約追加

1. NOT NULL制約の追加（tenantId, projectId）
2. 外部キー制約の追加
3. インデックスの最適化

詳細は [07_移行計画.md](./07_移行計画.md) を参照。

## データ量見積もり

### 初期想定（100 Tenant）

- Tenants: 100
- Users: 5,000 (平均50人/Tenant)
- Projects: 500 (平均5個/Tenant)
- Todos: 50,000 (平均100個/Project)

### ストレージ見積もり

- 1 Todo: ~1KB
- 50,000 Todos: ~50MB
- インデックス: ~20MB
- **合計: ~100MB** (初期規模として十分軽量)

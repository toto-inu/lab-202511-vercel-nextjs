# SaaS化プロジェクト概要

## 目的

現在のシンプルなTodoアプリケーションを、マルチテナント対応のSaaS型アプリケーションに進化させる。

## 背景

- 現状：単一環境で全ユーザーが同じデータを共有
- 目標：企業・組織単位でのデータ分離とプロジェクト管理機能の提供

## プロジェクトスコープ

### 実装する機能

1. **マルチテナント機能**
   - Tenant（組織・企業）単位でのデータ分離
   - ユーザーの複数Tenant所属対応
   - Tenant切り替えUI

2. **階層的なプロジェクト管理**
   - Tenant > Project > Todo の3階層構造
   - プロジェクト単位でのTodo管理

3. **段階的な権限モデル**
   - プラン制限（Free/Pro/Enterprise）
   - Tenantレベルのロール
   - Projectレベルのロール

4. **管理画面**
   - Tenant管理（作成・削除・設定）
   - プラン割り当て
   - ロール管理・権限設定
   - ユーザー管理

### 段階的な実装アプローチ

**Phase 1: データモデル構築**
- Prismaスキーマ拡張
- マイグレーション実行

**Phase 2: 認証・認可の拡張**
- マルチテナント対応の認証フロー
- 権限チェック機構

**Phase 3: コア機能実装**
- Project管理機能
- Tenant切り替え機能

**Phase 4: 管理画面**
- Next Admin拡張
- プラン・ロール管理UI

**Phase 5: 既存機能の移行**
- 既存Todoデータの移行
- Server Actionsの権限対応

## 設計原則

### 1. データ分離モデル

**論理的分離**を採用：
- 同一データベース内でtenantIdによる分離
- すべてのクエリでtenantIdフィルタを必須化
- 開発・保守の容易性を重視

### 2. 権限の階層構造

```
Plan制限（システムレベル）
  ↓
Tenant Role（組織レベル）
  ↓
Project Role（プロジェクトレベル）
```

上位の制限が優先され、下位の権限は上位の範囲内でのみ有効。

### 3. ユーザー体験

- **シンプルな導線**：複雑な権限を意識させない直感的UI
- **柔軟な切り替え**：複数Tenant所属時の快適な切り替え
- **段階的な学習曲線**：基本機能から高度な機能へ

## 非機能要件

### パフォーマンス
- ページ読み込み: 2秒以内
- Tenant切り替え: 1秒以内
- データ量: Tenant当たり10,000 Todo まで想定

### セキュリティ
- Tenant間データ漏洩の防止（必須クエリフィルタ）
- RBAC（Role-Based Access Control）の厳格な適用
- Clerk認証の継続利用

### スケーラビリティ
- 初期: 100 Tenant まで対応
- 将来: 1,000+ Tenant への拡張を考慮した設計
